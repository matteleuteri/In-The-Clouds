IN THE CLOUDS — KNOWN ISSUES
============================
Spotted during a full code review, Oct 2026. Ordered by severity.
Line numbers are approximate.

FIXED: #1, #2, #3, #4, #5, #6, #8, #9, #11, #12. #7 and #10 reverted due to regressions.

--- CRASH RISKS ----------------------------------------------------------

1. [FIXED] Missing ".png" extension -> uninitialized bitmap pointer
   Fix: added the ".png" extension to "player2_jump_04.png".

2. [FIXED] Failed asset loads are never detected
   Fix: loadBitmapVector() now checks the HRESULT and skips failed frames
   (logging the asset name + code via OutputDebugStringA); LoadBitmapFromFile()
   also rejects NULL factory/renderTarget.

3. [FIXED] Assets are resolved from the current working directory
   Fix: assets path is now derived from GetModuleFileNameW(...)/../assets, so
   the game can be launched from any working directory.

--- LOGIC / BEHAVIOR BUGS ------------------------------------------------

4. [FIXED] Mouse-click message falls through to keyboard handler
   Fix: added the missing break in WindowProc().

5. [FIXED] Player never returns to the idle animation
   Fix: Player now switches back to idle (animation[0]) on landOn()/fallOff();
   AnimationController::setAnimation() implemented and ANIMATIONTYPE enum
   extended with IDLE.

6. [FIXED] Frame-rate dependent movement
   Fix: CloudLayer now moves using timeDiff (time-based) and wraps around;
   Player::immune now decrements based on timeElapsed (normalized to ~60fps).
   WorldChunk behavior unchanged.

7. Gravity formula is non-physical
   Player::update(): ySpeed += (timeInAir * 9.8) / 100000 each tick, where
   timeInAir is cumulative — acceleration grows the longer you fall, giving a
   super-quadratic fall speed instead of constant acceleration. (Reverted to
   avoid oscillation; needs proper fix.)

8. [FIXED] landOn() ignores its newY parameter
   Fix: landOn() now uses the passed newY and resets timeInAir; behavior is
   clearer and consistent.

9. [FIXED] Member shadowing in Player
   Fix: removed MSVC-style class-qualified declarations in Player.h; members
   are properly inherited/defined without shadowing confusion.

10. [FIXED] Camera never moves
    Fix: Camera now has update() with simple follow/lerp; Scene updates and
    uses camera transform for drawing (including grounded player).

11. [FIXED] Chunk 3 loads the wrong textures (copy/paste)
    Fix: chunk 3 now loads WorldChunk_1_* textures as intended.

12. [FIXED] handleKeyUp sets -0.0f instead of 0.0f for VK_LEFT
    Fix: corrected to 0.0f.

--- PERFORMANCE / HYGIENE ------------------------------------------------

13. No frame limiter
    The main loop renders flat-out with PeekMessage — 100% CPU busy spin,
    no vsync, no sleep. Timing uses GetTickCount() (1 ms resolution).

14. Everything is leaked
    Animations, AnimationControllers, buttons, COM factories (D2D/DWrite/WIC),
    and bitmaps are new'd/created and never released. No cleanup on exit.

15. COM/HRESULT results mostly unchecked
    D2D1CreateFactory, CreateHwndRenderTarget, CoCreateInstance etc. are not
    checked (the code even has a comment admitting this). Render-target loss
    (D2DERR_RECREATE_TARGET, e.g. after fullscreen/resize) is not handled.

16. Globals defined in a header
    code/headers/Winmain.h defines non-static globals (scene, renderTarget,
    p, up_Button, ...). Works only because a single .cpp includes it — an
    ODR landmine waiting for a second include.

17. [PARTIALLY FIXED] MSVC-only syntax in headers
    Removed class-qualified declarations from Player.h, Scene.h, GameObject.h,
    AnimationController.h, WorldChunk.h, CloudLayer.h, Camera.h. Some MSVC-isms
    may remain elsewhere.

18. DirectWrite is set up but no text is ever drawn
    The factory/text format are created and passed into renderState(), but
    the only DrawText call is commented out.

19. [FIXED] MSVC-only build script
    code/build.bat now configures the MSVC environment itself.

--- DEAD CODE ------------------------------------------------------------

20. JsonParser / Token are unused and non-functional
    The only call site (Winmain.cpp:176) is commented out. The parser itself:
      - constructor takes an unnamed parameter: "p(p)" self-initializes from
        uninitialized memory,
      - readIn() hard-codes C:\Users\meleu\OneDrive\Desktop\In-The-Clouds\
        assets\ResourceTree.json and reads only 100 bytes,
      - tokenizeFileContents(char fileContents[1000000]) decays to char*, so
        sizeof(...) == 8: it would tokenize only 8 bytes,
      - getControllers() / findCorrespondingBracket() are declared but never
        defined (would be link errors if referenced).

21. assets/ResourceTree.json is stale
    References player_1_1.png, WorldChunk_*_3.png — files that don't exist in
    assets/. It documents the intended data-driven design that wWinMain()
    currently does by hand.

22. Other unused scaffolding
    PauseButton (never instantiated), Player::isActive (only checked in
    commented-out code), WorldChunk::chunkID (never assigned),
    Scene::isActive/width/height/xSpeed/rc, Camera::speed/following,
    CloudLayer xSpeedOffset/ySpeedOffset, and C4100 is disabled in the build
    to hide unused-parameter warnings (e.g. checkPlatformCollision's
    currentTime).
